# kabu-auto システム概要（AIプロンプト用）

---

## 1. 動作内容の簡単な説明

kabu-auto は、日本株（東証）を対象としたスイングトレード（数日〜数週間保有）の完全自動売買システム。auカブコム証券「kabuステーションAPI」に接続し、テクニカル指標 + LightGBM 機械学習のハイブリッド戦略でシグナルを生成・発注する。

- **稼働形態**: Windows ノートで 24 時間 365 日常駐
- **取引時間**: 東証前場 9:00〜11:30 / 後場 12:30〜15:30（平日のみ）
- **戦略**: MA/RSI/ボリンジャー/MACD のルールスコアと LightGBM の5日後上昇確率スコアを 0.5:0.5 で統合し、閾値を超えた銘柄を翌営業日に発注する
- **管理**: FastAPI 製の Web ダッシュボードをブラウザから操作（ポジション確認・銘柄追加・緊急停止など）

---

## 2. 使い方

### 初期設定
1. `config.yaml` に kabuステーション URL・ダッシュボード設定を記載
2. `.env` に API パスワード・Discord Webhook URL などの機密情報を記載
3. `python main.py` で起動（kabuステーションアプリも同時起動が必要）
4. ブラウザで `http://localhost:8080` を開き、初回ログイン → ウォッチリストに銘柄を登録

### 起動モード

| モード | 説明 |
|--------|------|
| `paper` | 仮想取引（実発注なし、終値でシミュレート）。既定 |
| `live` | 本番（kabuステーション API で実発注） |
| `dry_run` | ライブデータ取得・発注は承認待ちキューに積む |
| `semi_live` | 1件ずつダッシュボードで承認してから発注 |

### 日常の自動処理フロー

| 時刻 | 処理 |
|------|------|
| 16:00（毎日） | yfinance で当日 OHLCV を取得・DB 保存 |
| 16:20（平日） | シグナルスキャン（翌営業日の売買候補を生成） |
| 9:05（平日・live） | 前日シグナルを元に SELL 優先 → BUY の順で発注 |
| 9:00〜15:30（5分毎） | 損切り・ブレークイーブン・トレーリングストップチェック |
| 12:35（平日・live） | 後場スロット。朝に見送った**未保有**銘柄のみ拾い直す |
| 17:30（平日・任意） | X / Discord に日次損益レポートを自動投稿（含み損益・評価額つき） |
| 土曜 9:00（任意） | Discord に週次サマリを投稿 |
| 8:45（平日） | ハートビート（稼働中です）を通知 |
| 8:30（毎日） | API トークン更新。**毎営業日ここで認証が切れるのが通常運転** |
| 5分間隔 | 認証切れからの復帰試行（切れている間だけ・時間制限なし） |
| 15分間隔（平日8-23時） | 異常検知（エラー率・サイレント故障・未解決注文・損失上限） |
| 30秒間隔（任意） | Discord リモコンのコマンド受信 |
| 毎週日曜 2:00 | ML モデルの週次再学習 |

**休場日（土日・祝日・年末年始12/31-1/3）はシグナル生成・通知を行わない**
（`jpholiday` で判定。データ更新のみ実行する）。

### 認証まわり（運用上いちばん重要）

kabuステーションの認証は PC を起動したままでも**日をまたぐと切れる**。そのため:

1. 毎朝8:30に認証切れを検知 → 🔴 Discord 通知
2. 利用者が kabuステーションにログイン（**ID/パスワードと2段階認証は人が行う。自動化しない**）
3. kabu-auto が**時間制限なく**再接続を試み続け、ログインされ次第そのまま自動復帰
4. 復帰が場中かつ14時前なら、逃した朝の発注も取り返す（キャッチアップ）

kabuステーション本体が落ちている場合は kabu-auto が**アプリの起動だけ**を代行する
（1日3回まで。認証は人が行う）。

### ダッシュボードからできる操作
- ウォッチリスト管理（銘柄追加・削除・複数リスト切替）
- リスクプロファイル切替（`low_risk` / `high_risk`）
- kill switch（全取引の一時停止）・緊急全決済
- バックテスト実行・ML モデル手動再学習

## 3. 機能説明

### 戦略エンジン

| 機能 | 内容 |
|------|------|
| テクニカル指標 | MA(5/25/75日)・RSI(14日)・ボリンジャーバンド(20日・2σ)・MACD |
| ルールスコア | 上記指標の条件に応じて −1.0〜+1.0 のスコアを加減算 |
| MLモデル | LightGBM で「5日後に上昇するか」を予測。毎週日曜 2:00 に自動再学習。ロード時に SHA256 改ざん検知（fail-closed） |
| シグナル判定 | 統合スコア ≥ +0.25 → BUY / ≤ −0.25 → SELL |

### リスク管理（`low_risk` 既定値）

| 機能 | 設定値 | 説明 |
|------|--------|------|
| 損切り | −4% | 含み損が取得単価比 −4% を下回ったら成行売り |
| ブレークイーブン | +3% | ピーク含み益が +3% に達したら損切りラインを取得単価まで引き上げ |
| トレーリングストップ | −5% | ブレークイーブン発動後は「ピーク × 95%」で利益確定 |
| 流動性ガード | 設定値以下の銘柄 | 直近20日平均売買代金が閾値未満の銘柄への新規 BUY を抑止 |
| 大引け前 BUY 抑止 | 15:25 以降 | 大引け直前の新規エントリーを禁止 |
| 最大保有銘柄数 | 6銘柄 | 未約定 BUY も含めてカウント |
| セクター集中制限 | 30% | 同一業種への建玉が総資産の 30% を超えたら新規 BUY を停止 |
| 1銘柄投資比率 | 12% | 現金残高の 12% 以内に発注サイズを制限 |
| 当日損失上限 | 15,000円 | 実現損失＋含み損の合計が超過したら kill switch 自動作動（退出は継続可能） |

### 発注・約定管理

| 機能 | 説明 |
|------|------|
| 指値発注 | 通常エントリ/エグジット。タイムアウト（300秒）後に自動キャンセル |
| 成行発注 | 損切り・緊急全決済のみ（確実な約定を優先） |
| 3層モデル | OrderIntent（意図）→ BrokerOrder（ブローカー注文）→ Fill（約定明細）で管理。FIFO ロット会計で損益を確定 |
| 注文状態照合 | 15秒間隔でブローカーと照合し、WebSocket 取り逃しや再起動後の状態ズレを自動補正 |

### 通知・レポート

| 機能 | 説明 |
|------|------|
| Discord アラート | 認証切れ・約定・異常検知・kill switch 作動を即時通知。先頭の記号で緊急度が分かる（🔴要対応 / 🟡注意 / 🟢実行報告 / ⚪定期） |
| Discord リモコン | Bot にメンションして操作・照会（**ポート開放不要**）。`status` `positions` `today` `pnl` `orders` `reconnect` `launch` `halt` `resume` `help`。**秘密情報の授受と全決済は意図的に非実装** |
| 監視3層 | ①エラー率（時間窓のERROR多発）②ハートビート（生存信号。**来ないこと自体が異常**）③サイレント故障（場中のデータ途絶）。従来の「取引の結果」の監視では捉えられない障害を検知する |
| X 自動投稿 | 平日 17:30 に損益レポートを投稿（OAuth 1.0a・280文字） |
| Discord 日次/週次レポート | 17:30に日次（実現損益＋**含み損益・評価額**）、土曜9:00に週次サマリ（Webhook・2000文字） |

## 4. 50万円を資産としたときの具体的な動作例

**前提**: 運用資金 500,000円、`low_risk` プロファイル、`paper` モード

---

### 銘柄登録からデータ準備まで

1. ダッシュボードからウォッチリストに複数銘柄を追加（例: 株価 500円前後の 7203・6758・9984 など）
2. `/api/data/update` を実行 → yfinance で過去データを取得・DB 保存
3. MLモデル学習 → `models/lgb_model.pkl` 保存（SHA256 メタも生成）

---

### 発注サイズの計算

```
1銘柄あたりの上限金額 = 500,000円 × 12% = 60,000円
株価 520円の銘柄:
  最大単元数 = floor(60,000 ÷ (520 × 100)) = floor(60,000 ÷ 52,000) = 1単元
  購入株数   = 100株
  発注金額   = 52,000円

6銘柄フル投資時:
  使用資金   = 52,000円 × 6 = 312,000円（資産の 62%）
  現金留保   = 500,000 − 312,000 = 188,000円
```

---

### シグナル生成（毎日 16:20）

```
signal_scan() — 銘柄 7203（株価 520円）:

  ルールスコア:
    MA5 が MA25 を上抜け   → +0.4
    RSI < 30（売られすぎ） → +0.3
    合計 0.7 × 0.5 = +0.35

  MLスコア:
    LightGBM 上昇確率 0.65
    変換: (0.65 − 0.5) × 2 × 0.5 = +0.15

  統合スコア = 0.35 + 0.15 = 0.50 ≥ 0.25
  → BUY シグナルを DB に保存
```

---

### 発注実行（翌営業日 9:05）

```
morning_execution():

  リスクチェック:
    ✓ 注文数上限（0 / 100件）
    ✓ 当日損失 0円 < 15,000円
    ✓ 保有銘柄数 0 + 候補1 ≤ 6銘柄
    ✓ セクター集中 52,000円 < 500,000 × 30% = 150,000円
    ✓ 流動性 OK（平均売買代金が閾値以上）

  → 指値注文 @520円 × 100株 を kabuステーション API へ送信
  → WebSocket で約定通知受信
  → Position 作成・Fill 記録（取得単価 520円、peak_price = 520円）
```

---

### 損切り / 利益確定チェック（5分毎）

**シナリオ A: そのまま下落**

```
現在値: 498円
損益率 = (498 − 520) ÷ 520 = −4.2%  ≤ stop_loss_pct（−4%）

→ 損切り発動 → sell_market(reason="stop_loss") @成行
  損益 = (498 − 520) × 100 = −2,200円
  当日損失累計 = 2,200円（15,000円未満 → 取引継続）
  Discord に「損切り実行: 7203 −2,200円」を通知
```

**シナリオ B: 上昇後に反落（トレーリングストップ）**

```
peak_price が 537円まで上昇:
  含み益率 = (537 − 520) ÷ 520 = +3.3%  ≥ breakeven_trigger_pct（+3%）
  → ブレークイーブン発動
    損切りライン: avg_cost = 520円（取得単価まで引き上げ）
    トレーリングライン: 537 × 0.95 = 510.15円
    実効ストップ = max(520, 510.15) = 520円

さらに 560円まで上昇（peak_price = 560円に更新）:
  トレーリングライン: 560 × 0.95 = 532円
  実効ストップ = max(520, 532) = 532円

現在値が 532円を下回ったとき:
→ トレーリングストップ発動 → sell_market(reason="trailing_stop")
  損益 = (532 − 520) × 100 = +1,200円（利益確定）
```
