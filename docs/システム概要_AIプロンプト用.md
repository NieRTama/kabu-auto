# kabu-auto システム概要（AIプロンプト用）

記載内容は 2026-10-15 時点の `config.yaml`・`risk_profile.json`・実装に基づく。

---

## 1. 動作内容の簡単な説明

kabu-auto は、日本株（東証）を対象としたスイングトレード（数日〜数週間保有）の自動売買システム。三菱UFJ eスマート証券（旧 auカブコム証券）の「kabuステーションAPI」に接続し、テクニカル指標と LightGBM 機械学習を組み合わせたスコアでシグナルを生成・発注する。

- **稼働形態**: Windows PC で常駐（タスクスケジューラ `\kabu\kabu-auto` がログオン時に起動）
- **取引時間**: 東証前場 9:00〜11:30 / 後場 12:30〜15:30（平日のみ）
- **戦略**: MA/RSI/ボリンジャー/MACD のルールスコアと LightGBM のスコアを 0.5:0.5 で統合し、閾値を超えた銘柄を翌営業日に発注する
- **管理**: FastAPI 製の Web ダッシュボード（ポジション確認・銘柄追加・緊急停止など）と Discord リモコン

---

## 2. 使い方

### 初期設定
1. `config.yaml` に kabuステーション URL・ダッシュボード設定を記載
2. `.env` に API パスワード・Discord Webhook URL などの機密情報を記載
3. 起動: 本番環境ではタスクスケジューラ `\kabu\kabu-auto`（`scripts\run_autostart.bat`）がログオン時に起動する。手動起動は `switch-mode.bat` または `python main.py`
4. ブラウザで `http://localhost:8080` を開き、ログイン → ウォッチリストに銘柄を登録

### 取引モード

| モード | 説明 |
|--------|------|
| `paper` | 仮想取引（実発注なし、終値でシミュレート） |
| `dry_run` | 実口座の板・余力を読むが発注しない |
| `semi_live` | 承認キューに積み、ダッシュボードで承認した分だけ発注 |
| `live` | 本番（kabuステーション API で実発注）。2026-08-25 から本番稼働中 |

### 日常の自動処理フロー（平日）

| 時刻 | 処理 |
|------|------|
| 8:20 | RDP切断で残ったコンソールセッションの検知・復帰（`session_check`） |
| 8:25 | 日次リスクカウンタのリセット（`risk_reset`） |
| 8:30 | 完全自動ログイン（kabuステーションの起動・ログイン・2段階認証入力） |
| 8:35 | API トークン更新（`token_refresh`） |
| 8:45 | ハートビート（稼働中です）を通知 |
| 9:05 | 前営業日の signal_scan バッチを元に SELL → BUY の順で発注（live） |
| 9:00〜11:30 / 12:30〜15:30（5分毎） | 損切り・ブレークイーブン・トレーリングストップの判定 |
| 12:35 | 後場スロット。朝に見送った未保有銘柄のBUYを再判定（live） |
| 8〜23時（15分毎） | 異常検知（エラー率・サイレント故障・未解決注文・損失上限） |
| 16:00（毎日） | yfinance で OHLCV を取得・DB 保存 |
| 16:20 | シグナルスキャン（翌営業日の売買候補を生成） |
| 17:00（毎日） | DB バックアップ |
| 17:30 | Discord に日次損益レポート（X は無効） |
| 18:30（毎日） | 日次運用概要を `log/ops_daily/` へ出力（Windowsタスク、2026-11-14まで） |
| 20:00（毎日） | Gmail 認証の失効予告チェック |

その他: 土曜 9:00 に Discord へ週次サマリ、日曜 2:00 に ML モデルの週次再学習、認証切れ中は5分毎に復帰試行（時間制限なし）、Discord リモコンは30秒毎にコマンド受信。

休場日（土日・祝日・年末年始12/31-1/3）はシグナル生成・ハートビート・日次レポートを行わない（`jpholiday` と独自判定。データ更新は実行する）。

### 認証まわり

kabuステーションの認証は PC を起動したままでも日をまたぐと切れる（毎営業日1回）。

1. 平日8:30 に完全自動ログイン（`broker_full_login`）がログインする。ワンタイムパスワードは WSL2 側の外部リポジトリが Gmail API で取得する（本体プロセスは秘密情報を扱わない）
2. 失敗した場合は 🔴 Discord 通知 → 利用者が手動でログイン
3. kabu-auto は時間制限なく再接続を試み、ログインされ次第自動で復帰する
4. 復帰が場中かつ14時前なら、逃した朝の発注を実行する（キャッチアップ）

kabuステーション本体が起動していない場合は、kabu-auto がアプリを起動する（1日3回まで）。
証券会社はログイン時のパスキー必須化を「2026年10月末目標」と告知しており（実施日未確定）、必須化後は完全自動ログインが動作しない可能性がある。

### ダッシュボードからできる操作
- ウォッチリスト管理（銘柄追加・削除・複数リスト切替）
- リスクプロファイル切替（`low_risk` / `high_risk` / カスタム）
- kill switch（全取引の一時停止）・緊急全決済
- バックテスト実行・ML モデル手動再学習

## 3. 機能説明

### 戦略エンジン

| 機能 | 内容 |
|------|------|
| テクニカル指標 | MA(5/25/75日)・RSI(14日)・ボリンジャーバンド(20日・2σ)・MACD |
| ルールスコア | 上記指標の条件に応じて −1.0〜+1.0 のスコアを加減算 |
| MLモデル | LightGBM。ラベルはトリプルバリア法（最大保有10営業日）。毎週日曜 2:00 に自動再学習。ロード時に SHA256 と特徴量セットを検証（不一致は fail-closed） |
| シグナル判定 | 統合スコアがアクティブなリスクプロファイルの `buy_threshold` 以上で BUY、`sell_threshold` 以下で SELL（low_risk: ±0.14 / high_risk: ±0.08） |

### リスク管理（リスクプロファイル）

| 項目 | low_risk | high_risk |
|------|------|------|
| 損切り | −4% | −15% |
| 1銘柄投資比率（余力に対する） | 12% | 50% |
| 最大保有銘柄数（未約定BUYを含む） | 6銘柄 | 8銘柄 |
| セクター集中制限 | 30% | 55% |
| 当日損失上限 | 15,000円 | 60,000円 |
| 買い/売り閾値 | ±0.14 | ±0.08 |

2026-10-15 時点のアクティブは、`high_risk` を複製したカスタムプロファイル `20261009`（値は `high_risk` と同一）。

プロファイル共通（`config.yaml` の `trading`・`liquidity`）:

| 機能 | 設定値 | 説明 |
|------|--------|------|
| ブレークイーブン | +2% | ピーク含み益が +2% に達したら損切りラインを取得単価まで引き上げ |
| トレーリングストップ | 4% | ブレークイーブン発動後は「ピーク × 96%」でも売却 |
| 流動性ガード | 0（無効） | 直近20日平均売買代金が閾値未満の銘柄への新規 BUY を抑止 |
| 大引け前 BUY 抑止 | 0分（無効） | 大引け前の指定分数は新規BUYを見送る |
| 当日損失上限の対象 | 実現損失＋含み損 | 超過したら kill switch 自動作動（退出は継続） |

### 発注・約定管理

| 機能 | 説明 |
|------|------|
| 指値発注 | 通常のエントリ/エグジット。板の現在値を指値にする。300秒（`order_timeout_seconds`）で未約定ならキャンセル |
| 成行発注 | 損切り・トレーリングストップ・緊急全決済 |
| 3層モデル | OrderIntent（意図）→ Trade（ブローカー注文）→ Fill（約定明細）で管理。FIFO ロット会計で損益を確定 |
| 注文状態照合 | 15秒間隔でブローカーと照合し、WebSocket の取り逃しや再起動後の状態ズレを補正 |

### 通知・レポート

| 機能 | 説明 |
|------|------|
| Discord アラート | 認証切れ・約定・異常検知・kill switch 作動を通知。先頭の記号で重要度を示す（🔴要対応 / 🟡注意 / 🟢実行報告 / ⚪定期）。一時的な送信失敗は最大3回送信 |
| Discord リモコン | Bot へのメンション（30秒ポーリング）またはスラッシュコマンドで操作・照会（ポート開放不要）。`status` `positions` `today` `pnl` `summary` `orders` `reconnect` `launch` `full_login` `gmail_auth` `halt` `resume` `help`。秘密情報の授受と全決済は意図的に非実装 |
| 監視3層 | ①エラー率（時間窓での多発。ERRORとWARNINGで別閾値）②ハートビート（生存信号。届かないこと自体を異常とする）③サイレント故障（場中のデータ取得途絶。一度も成功していない場合は開場からの経過時間で判定） |
| 認証状態の判定 | 実際のAPI応答（401）で判定する。全REST呼び出しは `KabuClient._request()` を通り、401なら `broker_auth.mark_expired()` が呼ばれる（2026-09-02 にトークン更新の成否だけで判定していたため場中の失効を検知できなかったことへの対策） |
| Discord 日次/週次レポート | 平日17:30に日次（実現損益＋保有建玉の評価額・含み損益）、土曜9:00に週次サマリ |
| X 自動投稿 | 平日17:30に損益レポート（280文字）。現在は無効（`x.enabled: false`） |
| 日次運用概要 | 毎日18:30に `log/ops_daily/ops_daily_YYYY-MM-DD.md` を出力。Discord の `summary` でも取得 |

## 4. 動作例（余力50万円・low_risk・live）

**前提**: 証券口座の余力 500,000円、`low_risk` プロファイル、`live` モード

### 銘柄登録からデータ準備まで

1. ダッシュボードからウォッチリストに銘柄を追加（追加時に過去データを自動取得）
2. MLモデル学習 → `models/lgb_model.pkl` 保存（SHA256 メタも生成）

### 発注サイズの計算

```
1銘柄あたりの上限金額 = 余力 500,000円 × 12% = 60,000円
株価 520円の銘柄:
  最大単元数 = floor(60,000 ÷ (520 × 100)) = floor(60,000 ÷ 52,000) = 1単元
  購入株数   = 100株
  発注金額   = 52,000円
```

余力は発注ごとにAPIで取得し直すため、2銘柄目以降の上限は減った余力に対して計算される。

### シグナル生成（前営業日 16:20）

```
signal_scan() — 銘柄 7203（株価 520円）:

  ルールスコア:
    MA5 が MA25 を上抜け   → +0.4
    RSI < 30（売られすぎ） → +0.3
    合計 0.7 × 0.5 = +0.35

  MLスコア:
    上昇確率 0.65
    変換: (0.65 − 0.5) × 2 × 0.5 = +0.15

  統合スコア = 0.35 + 0.15 = 0.50 ≥ 0.14（low_risk の buy_threshold）
  → BUY シグナルを DB に保存
```

### 発注実行（翌営業日 9:05）

```
morning_execution():

  リスクチェック:
    ✓ 注文数上限（0 / 100件）
    ✓ 当日損失 0円 < 15,000円
    ✓ 保有銘柄数 0 + 候補1 ≤ 6銘柄
    ✓ セクター集中が上限未満
    ✓ 購入株数が1単元以上

  → 指値注文 @520円（板の現在値）× 100株 を kabuステーション API へ送信
  → WebSocket で約定通知受信
  → Position 作成・Fill 記録（取得単価 520円、peak_price = 520円）
```

### 損切り / 利益確定チェック（5分毎）

**シナリオ A: そのまま下落**

```
現在値: 499円
損益率 = (499 − 520) ÷ 520 = −4.04%  ≤ stop_loss_pct（−4%）

→ 損切り発動 → sell_market(reason="stop_loss") @成行
  損益 = (499 − 520) × 100 = −2,100円
  当日損失累計 = 2,100円（15,000円未満 → 取引継続）
  Discord に損切り実行を通知
```

**シナリオ B: 上昇後に反落（トレーリングストップ）**

```
peak_price が 531円まで上昇:
  含み益率 = (531 − 520) ÷ 520 = +2.1%  ≥ breakeven_trigger_pct（+2%）
  → ブレークイーブン発動
    損切りライン: avg_cost = 520円（取得単価まで引き上げ）
    トレーリングライン: 531 × 0.96 = 509.76円
    実効ストップ = max(520, 509.76) = 520円

さらに 560円まで上昇（peak_price = 560円に更新）:
  トレーリングライン: 560 × 0.96 = 537.6円
  実効ストップ = max(520, 537.6) = 537.6円

現在値が 537.6円を下回ったとき:
→ トレーリングストップ発動 → sell_market(reason="trailing_stop")
  損益 ≒ (537 − 520) × 100 = +1,700円（利益確定）
```

### 日次レポート（17:30・Discord）

```

モード: ライブ（本番・実発注）

当日: +1,700円 (+0.3%) 勝率100%

```
