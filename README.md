# kabu-auto

東京証券取引所の株式を対象にした、Windows 向けのスイングトレード自動売買システム。
auカブコム証券の kabuステーションAPI を使い、ルールベースと機械学習（LightGBM）を組み合わせたシグナルで、数日〜数週間単位のポジションを自動で売買・管理する。

> **実際の資金で注文を出すソフトウェアです。** 必ず `paper`（ペーパートレード）で十分に動作を確認してから本番に移行してください。末尾の[免責事項](#免責事項リスク開示)も必ず読んでください。

---

## できること

| 分類 | 機能 |
|---|---|
| 売買 | 毎日引け後に翌営業日の売買候補を選び、翌朝 9:05 に自動発注する。朝に見送った銘柄は 12:35 に拾い直す |
| 保有管理 | 損切り・ブレークイーブン・トレーリングストップを場中5分ごとに判定する。保有中の銘柄は、ウォッチリストに入っているかどうかに関わらず必ず監視する |
| リスク制御 | 1銘柄あたりの上限・最大保有数・セクター集中・1日の注文数・当日損失の上限。リスクプロファイル（守り/攻め）をワンクリックで切り替えられる |
| 安全装置 | 取引モードの段階移行、起動前の安全確認、取引停止スイッチ、緊急全決済、実口座とDBのズレの自動検知 |
| 無人運用 | kabuステーションの起動〜ログイン〜2段階認証を平日 8:30 に自動実行する。認証が切れたら自動で再接続する |
| 遠隔操作 | Discord から状態確認・取引停止/再開・再接続ができる |
| 通知 | 異常時アラート・毎朝の稼働通知・日次/週次の損益レポートを Discord に送る |
| 分析 | Webダッシュボード（損益・ポジション・取引履歴・シグナル・パフォーマンス分析）、バックテスト、MLモデルの精度推移 |
| 学習 | 毎週日曜に MLモデルを自動で再学習する |
| バックアップ | DBを毎日自動バックアップする。DB・モデル・設定一式をPCの外へ退避するスクリプトも付属 |

## 動作の流れ

平日の1日は次のように動く（時刻はすべて日本時間）。

```
08:25  日次カウンタ（注文数・損失額）をリセット
08:30  kabuステーションに自動ログイン
08:35  APIトークンを更新
08:45  「稼働中です」を Discord に通知
08:50  緊急決済トークンを Discord に投稿（前日の投稿は削除）
09:05  前日のシグナルをもとに発注（売り → 買いの順）
09:00〜15:55  5分ごとに損切り・利確を判定
12:35  朝に見送った銘柄を拾い直す
16:00  当日の株価データを取得（土日も実行）
16:20  翌営業日の売買候補をスキャン
17:00  DBバックアップ（土日も実行）
17:30  日次損益レポートを投稿
```

このほか、常時実行するジョブと週次のジョブがある。

| 間隔 | 処理 |
|---|---|
| 15秒ごと | 注文状態を証券会社と照合する（場中のみ）。建玉のズレを検知したら取引を止める |
| 30秒ごと | Discord の新着コマンドを確認する |
| 5分ごと | ログイン認証が切れている間だけ再接続を試みる |
| 15分ごと（平日 8〜23時） | 未解決注文・損失上限への接近・停止スイッチの状態を点検し、異常があれば通知する |
| 毎週土曜 9:00 | 週次の成績レポートを投稿する |
| 毎週日曜 2:00 | MLモデルを再学習する |

祝日は休場日として扱い、ログイン・トークン更新・発注・シグナルスキャン・レポート投稿を行わない。土曜深夜の kabuステーションのメンテナンス時間帯も自動で避ける。

### 売買シグナルの仕組み

1. **ルールスコア**: 移動平均のクロス・RSI・ボリンジャーバンド・MACD からスコアを計算する。
2. **MLスコア**: LightGBM で「一定期間内に利益確定ラインへ先に届く確率」を予測する（トリプルバリア法でラベル付けした過去データで学習）。
3. **合成スコア** = ルールスコア × `rule_weight` ＋ MLスコア × `ml_weight`。これが買い閾値を超えたら買い、売り閾値を下回ったら売りの候補になる。
4. 候補は、資金・最大保有数・セクター集中・当日損失の上限を通過したものだけが発注される。

## 必要環境

| 項目 | 要件 |
|---|---|
| OS | Windows（kabuステーションが Windows 専用のため） |
| Python | 3.11 以上 |
| 証券口座 | auカブコム証券（kabuステーションAPI の利用申込が必要） |
| PC設定 | スリープを無効にする（電源オプション → スリープしない） |

起動が極端に遅い（数分以上かかる）場合は、Windows Defender のリアルタイム保護が Python のライブラリをスキャンしていることが多い。Windowsセキュリティの「除外の追加」で、Python のインストール先とこのリポジトリを除外すると解消する（管理者権限が必要）。

## セットアップ

はじめての場合は [SETUP-CHECKLIST.md](SETUP-CHECKLIST.md) の順に進めると安全。

### 1. kabuステーションの準備

1. auカブコム証券で口座を開設する。
2. kabuステーションをインストールして起動し、API を有効にする（ツール → kabuステーションAPI）。

### 2. パッケージのインストール

```bash
pip install -r requirements.txt
```

### 3. パスワードの設定（.env）

kabuステーションの **APIパスワード**（kabuステーションの「APIシステム設定」で設定するもの。証券口座のログインパスワードや取引暗証番号とは別物）は `.env` に書く。`config.yaml` には書かない。

```bash
copy .env.example .env
```

```
KABU_API_PASSWORD=kabuステーションのAPIパスワード
```

`.env` は git の追跡対象外なので、誤ってコミットされない。

### 4. config.yaml の確認

最初は `paper` のまま動かす。

```yaml
trading:
  mode: "paper"

dashboard:
  host: "0.0.0.0"        # LAN内の他端末からも見る場合。同じPCだけなら "127.0.0.1"
  emergency_token: ""    # 空欄なら起動のたびにランダム生成する
```

### 5. ウォッチリストの登録

売買の対象にする銘柄は `watchlists.json` に登録する。起動後はダッシュボードの「ウォッチリスト管理」から追加・削除・切替ができる（会社名とセクターは自動で取得する）。

```json
{
  "active": "メイン",
  "lists": {
    "メイン": [
      { "code": "7203", "name": "トヨタ自動車", "sector": "Consumer Cyclical" }
    ],
    "高配当株": []
  }
}
```

- 新規の売買候補は「アクティブな1リスト」から選ぶ。リストは用途ごとに複数持てる。
- 保有中の銘柄は、どのリストに入っているかに関わらず損切り・利確の監視対象になる。
- 英字を含む証券コード（例: `336A`）は大文字で登録する。

### 6. 起動

```bash
python main.py
```

ブラウザで `http://localhost:8080` を開くとダッシュボードが表示される。

- 初回はログイン画面でユーザーIDとパスワードを作成する（`data/auth.json` にハッシュで保存される）。
- 緊急決済トークンは起動時のコンソールに1回だけ表示される（ログファイルには残らない）。Discord リモコンを設定していれば、平日の朝にも投稿される。
- 同じPCで二重に起動しようとすると、2つ目は起動を中断する。

### 7. 初回のデータ取得と学習

株価データは毎日 16:00 に自動で取得するが、すぐに試したい場合は手動で実行できる。

```bash
curl -X POST http://localhost:8080/api/data/update    # 過去データを取得（数分かかる）
curl -X POST http://localhost:8080/api/model/retrain  # MLモデルを学習
curl http://localhost:8080/api/model/latest           # 学習結果を確認
```

## 取引モード

| モード | 動作 | 実発注 | 実口座の読み取り |
|---|---|:---:|:---:|
| `paper` | 仮想の資金で売買をシミュレートする | × | × |
| `dry_run` | 実口座の板・余力を読むが、発注はせず記録だけ残す | × | ○ |
| `semi_live` | 新規注文を承認待ちに積み、ダッシュボードで承認した分だけ発注する（損切りと緊急決済は承認なしで即時） | ○ | ○ |
| `live` | すべて自動で発注する | ○ | ○ |

`paper` → `dry_run` → `semi_live` → `live` の順に移行する。

- `semi_live` と `live` は、環境変数 `CONFIRM_LIVE_TRADING=true` を付けないと起動しない（誤起動の防止）。
- `switch-mode.bat` をダブルクリックすると、メニューからモードを切り替えられる。接続先（本番 18080 / 検証 18081）と、`.env` の APIパスワード（`KABU_API_PASSWORD_LIVE` / `KABU_API_PASSWORD_VERIFY` から選ぶ）もあわせて切り替わる。詳しくは [docs/モード切替ガイド.md](docs/モード切替ガイド.md)。
- `config.yaml` と `.env` は起動時に1回だけ読む。変更したら再起動する。

### 起動前の安全確認

`paper` 以外では、起動時に次の項目を自動で確認する。実発注モードでは、1つでも致命的な項目が失敗すれば起動を中断する。

- 証券会社APIにつながるか
- 状態が不明な注文（`UNKNOWN` / `CANCEL_FAILED`）が残っていないか
- ダッシュボードのポートが空いているか
- 実発注モードが検証用のポート（18081）を向いていないか
- 取引停止スイッチが入ったままでないか（警告のみ）

## 無人運用

### 自動ログイン

kabuステーションのログイン認証は、PCを起動したままでも日をまたぐと切れる。そのため毎営業日1回のログインが必要になる。

`runtime.broker_full_login_enabled: true`（既定）にすると、平日 8:30 に kabuステーションの起動・ログイン・2段階認証の入力までを自動で行う。ワンタイムパスワードは Gmail API で受け取る（WSL2 側に別途 `kabusapi-auto-login-template` の導入が必要）。Discord の `full_login` コマンドでいつでも手動で実行できる。

### 認証切れからの自動復帰

ログイン認証が切れると、次のように動く。

1. 新規の発注を止める。損切り・トレーリング・緊急決済などの手じまいは止めない。
2. Discord に「再ログインが必要です」と通知する。
3. 5分ごとに再接続を試み、ログインされ次第そのまま取引を再開する（時間の制限はない）。
4. 朝 9:05 の発注を逃していた場合、復帰した時刻が場中かつ締切（既定 14:00、`trading.catchup_deadline_hour`）より前なら、逃した分をその場で発注する。その日すでに買った銘柄は対象外。

### PCの起動時に自動で立ち上げる

Windows のタスクスケジューラに `scripts\run_autostart.bat` を登録する。

- 自動ログインは画面操作を伴うため、タスクは「ユーザーがログオンしているときのみ実行」（ログオン種別 `Interactive`）にし、トリガーは「ログオン時」にする。
- そのため、Windows の自動サインインを設定していない場合は、PCにサインインした時点で起動する。

起動時にまだ kabuステーションにつながらない場合、`runtime.wait_for_broker_minutes`（既定 0 = 待たずに中断）の分だけ接続を待つ。待機中は Discord に通知する。

## Discord 連携

設定方法は [docs/通知設定ガイド.md](docs/通知設定ガイド.md) と [docs/日次レポート投稿ガイド.md](docs/日次レポート投稿ガイド.md) を参照。どれも任意で、設定しなければ無効のまま動く。

| 機能 | 必要な設定（`.env`） | 内容 |
|---|---|---|

| 日次/週次レポート | `config.yaml` の `discord_report.webhook_url` | 平日 17:30 に日次、土曜 9:00 に週次の損益を投稿する |
| リモコン | `DISCORD_BOT_TOKEN` / `DISCORD_BOT_CHANNEL_ID` / `DISCORD_ALLOWED_USER_ID` | 下記のコマンドを受け付ける |

### リモコンのコマンド

Bot にメンションして送る（例: `@kabu-auto status`）。discord.py を入れていればスラッシュコマンド（`/status`）でも使える。許可したユーザー以外からのコマンドは実行しない。

| コマンド | 内容 |
|---|---|
| `status` | 稼働状況（モード・発注可否・認証・未解決注文） |
| `positions` | 保有中の銘柄と含み損益 |
| `today` | 本日の約定と確定損益 |
| `pnl` | 損益サマリ（当日/週次/月次/累計） |
| `orders` | 未約定の注文 |
| `halt [理由]` | 取引を停止する（手じまいは続く） |
| `resume` | 取引を再開する |
| `reconnect` | 認証切れのとき、すぐに再接続を試す |
| `launch` | kabuステーションを起動する（ログインは手動） |
| `full_login` | kabuステーションの起動からログインまでを自動で行う |
| `help` | コマンド一覧 |

緊急全決済は、誤操作したときの損害が大きいため Discord からは実行できない。ダッシュボードから緊急決済トークンを使って行う。リモコン用チャンネルには平日の朝に緊急決済トークンが投稿されるので、そのチャンネルは自分だけが見られる設定にしておくこと。

## Webダッシュボード

`http://localhost:8080` で開く。10秒ごとに自動で更新される。

- **損益**: 累積損益・含み損益・今日/月初来/年初来の損益、日次と累積のグラフ
- **成績**: 勝率・最大ドローダウン・シャープレシオ・プロフィットファクター・銘柄別/セクター別の損益
- **ポジションと履歴**: 保有銘柄、取引履歴、シグナル履歴
- **取引ジャーナル**: 確定した取引の一覧。発注の根拠（スコア・損切り理由）を自動で記録し、メモも残せる
- **日次レポート**: 日ごとの確定損益・約定件数・勝率
- **異常バナー**: 未解決注文・損失上限への接近・停止スイッチの状態
- **設定操作**: ウォッチリスト、リスクプロファイル、バックテスト、MLモデルの精度推移

LAN の他の端末から開く設定（`host: "0.0.0.0"`、既定）では、ログイン認証が自動で有効になる。通信は暗号化されない HTTP なので、信頼できる LAN の中だけで使うこと。curl などのプログラムからは、起動時に表示される `X-API-Token` で認証する。

### 緊急時の操作

「緊急操作」カードの操作には、緊急決済トークン（`X-Emergency-Token`）が必要。

| 操作 | 内容 |
|---|---|
| 緊急全決済 | 全保有銘柄を成行で即時に売る。本番では証券会社側の実際の保有数量を基準にする。保有数量の取得や未約定注文の取消に失敗した場合は、状態が不確かなまま売りを重ねないよう中断して通知する |
| 取引停止スイッチ | 新規の発注をすべて止め、未約定の買い注文を取り消す（全決済も選べる）。損切りと緊急決済は停止中も動く。停止状態は再起動しても残る。状態が不明な注文が残っている間は解除できない |
| 保護ストップ | 証券会社側に逆指値の損切り注文を置く。PCや kabuステーションが止まっていても損切りが効く |

実口座とDBの保有数量のズレを照合ジョブが検知したときも、取引停止スイッチが自動で入る。

### トラブル時の手順

実口座とDBが食い違っている疑いがあるとき（状態が不明な注文が残る・約定したかわからない など）:

1. 取引停止スイッチを入れる。
2. kabuステーションや証券会社のアプリで、実際の注文と保有を確認する。
3. 状態が不明な注文を、実態に合わせて手動で決済または取消する（残っている間は新規発注も再開もできない）。
4. 解消したら停止スイッチを解除する。

詳しくは [docs/運用Runbook.md](docs/運用Runbook.md) を参照。

## リスク管理

### リスクプロファイル

ダッシュボードの「リスクプロファイル」から、守りと攻めをワンクリックで切り替えられる。選んだプロファイルは `risk_profile.json` に保存され、再起動しても残る。

| | ローリスク（既定） | ハイリスク |
|---|---|---|
| 1銘柄あたりの上限（資金比） | 12% | 50% |
| 損切りライン | -4% | -10% |
| 最大保有銘柄数 | 6 | 8 |
| セクター集中の上限 | 30% | 55% |
| 当日損失の上限 | ¥15,000 | ¥60,000 |
| 売買閾値 | ±0.14 | ±0.08 |

2つの定義は `config.yaml` の `risk_profiles` で変えられる。既存のプロファイルを複製してカスタムのプロファイルも作れる（作成・比較・書き出し・取り込み・変更履歴に対応）。範囲外の値は丸めずにエラーにする。実発注モードでの切り替えには確認が入る。

### プロファイル以外の設定（config.yaml の trading）

```yaml
trading:
  breakeven_trigger_pct: 0.02  # 含み益が+2%に届いたら、損切りラインを建値へ引き上げる（0で無効）
  trailing_stop_pct: 0.04      # その後、ピークから-4%下がったら利益を確定する（0で無効）
  order_timeout_seconds: 300   # 約定しない注文を取り消すまでの秒数
  daily_order_limit: 100       # 1日の最大注文数
  paper_initial_capital: 500000  # paper の初期資金
```

当日の注文数と損失額はDBからも復元するので、上限に達したあとに再起動しても制限は解除されない。

損切りと手じまいは成行で発注する。ただし翌朝の窓開け（ストップ高/安など）では、損切りラインを大きく超えて約定することがある。

## 戦略の設定（config.yaml の strategy）

```yaml
strategy:
  ma_short: 5           # 短期移動平均（日）
  ma_mid: 25            # 中期移動平均
  ma_long: 75           # 長期移動平均
  rsi_period: 14
  rsi_oversold: 30
  rsi_overbought: 70
  bb_period: 20
  bb_std: 2.0
  ml_weight: 0.5        # 合成スコアでの ML の重み
  rule_weight: 0.5      # 合成スコアでのルールの重み
  engine_version: "legacy"
```

買い/売りの閾値はリスクプロファイルの値が使われる。閾値が実際のスコアの分布より高すぎると、取引がまったく発生しない。運用を始めたら `/api/signals` でスコアの分布を確認して調整する。

`engine_version: "v2"` にすると、再学習とバックテストが新しい評価エンジン（リークを防ぐ時系列交差検証、資金制約込みのシミュレーション）に切り替わる。v2 で学習したモデルは候補として保存されるだけで、運用中のモデルは明示的に昇格させるまで変わらない。詳しくは [docs/詳細設計書.md](docs/詳細設計書.md) の §1.42 を参照。

## バックテスト

ダッシュボードの「バックテスト実行」から、または API で実行する。

```bash
curl -X POST http://localhost:8080/api/backtest/run \
  -H "Content-Type: application/json" \
  -d '{"symbol": "7203", "start": "2023-01-01", "end": "2023-12-31", "use_ml": false}'
```

- 各日の時点で手に入るデータだけを使って判定する（未来のデータは使わない）。
- ML を使う場合は、バックテスト期間より前のデータだけで学習する。
- `buy_threshold` / `sell_threshold` を渡すと、その実行だけ閾値を変えて試せる（運用中の設定は変わらない）。
- 結果は保存され、ダッシュボードで一覧・詳細・実取引との比較を確認できる。

## MLモデルの精度推移

再学習のたびに、交差検証の精度・AUC・Brierスコア・学習件数・特徴量の重要度を記録し、ダッシュボードにグラフで表示する。

## バックアップと復元

| 種類 | 対象 | 保存先 | 実行 |
|---|---|---|---|
| 日次DBバックアップ | `data/kabu_auto.db` | `data/backups/`（同じディスク・30日分） | 毎日 17:00 に自動 |
| 状態バックアップ | DB・モデル・設定・運用状態・`.env` | OneDrive など PC の外 | `scripts\backup_state.ps1` を手動で実行 |

日次バックアップは同じディスクにあるため、PCが壊れると一緒に失われる。状態バックアップも併用すること。

```powershell
powershell -File scripts\backup_state.ps1                    # 既定: OneDrive\kabu-auto に7世代
powershell -File scripts\backup_state.ps1 -NoSecrets         # .env と data/auth.json を含めない
powershell -File scripts\backup_state.ps1 -Dest "G:\backup" -Keep 14
```

- 稼働中のまま実行してよい。
- 既定では ZIP に APIパスワードが平文で入る。共有リンクは作らないこと。

**復元**: ZIP に入っている `RESTORE.md` の手順に従う（そのバックアップ時点のコミットに合わせてコードを取得し、ZIP を展開する）。復元後はまず `paper` で起動し、DBの保有と実口座の保有が一致していることを確かめてから `live` に戻す。

## その他

- **ログ**: `log/` に日付ごとに出力される。INFO 以下と WARNING 以上は別のファイル（`kabu_auto_warning_YYYY-MM-DD.log`）に分かれる。既定で15日分を残す。
- **注文数の制限**: kabuステーションAPI には1日の注文数の制限がある。
- **即時反映される設定**: ウォッチリストとリスクプロファイルは、ダッシュボードで変えると再起動なしで次のジョブから反映される。
- **外部送信**: Discord 連携を設定すると、取引情報（銘柄・数量・価格・損益）が Discord に送られる。
- **テスト**: `pytest tests/` で実行する。push と pull request のたびに GitHub Actions でも実行される。
